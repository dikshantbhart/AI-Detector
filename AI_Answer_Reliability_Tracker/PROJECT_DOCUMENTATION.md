# AI Answer Reliability Tracker — Comprehensive System Documentation

> **Meta Description:**  
> A structured evidence-based tracking and auditing system designed to assess, score, and verify AI-generated assertions against corroborating sources, confidence ratings, and credibility audits using SQLite, the Minimal Cream & Orange design theme, Figtree typography, and fully responsive media queries.

---

## 1. Abstract & Problem Statement

Artificial Intelligence (LLMs and generative answer engines) frequently produces assertions with varying degrees of factual accuracy, hallucinations, and unverified generalisations. Without a dedicated evidence-tracking infrastructure, researchers, students, and fact-checkers struggle to systematically catalog statements, link primary citations, track confidence levels, and record audit decisions.

The **AI Answer Reliability Tracker (Advanced Edition)** resolves this by establishing a disciplined relational workflow. The system enables users to:
1. Log atomic claim statements generated by AI systems.
2. Attribute claims to specific knowledge domains / categories.
3. Quantify subjective assessment confidence from 0% to 100%.
4. Catalog corroborating or refuting sources with objective credibility scores (1 to 5 stars).
5. Map many-to-many relationships between claims and sources.
6. Conduct status verification audits (`Unverified` &rarr; `Verified`, `Disputed`, or `Rejected`) with permanent audit logs.
7. Export comprehensive reliability reports to CSV.

## 5. Relational Database Architecture

The SQLite schema incorporates foreign keys, check constraints, indexes, an aggregate summary view, and an automated audit trigger.

### Relational Schema (3NF)

```sql
PRAGMA foreign_keys = ON;

-- 1. USERS: Authentication and audit attribution
CREATE TABLE users (
    user_id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    role TEXT NOT NULL DEFAULT 'user',
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 2. CLAIMS: Atomic factual assertions
CREATE TABLE claims (
    claim_id INTEGER PRIMARY KEY AUTOINCREMENT,
    claim_text TEXT NOT NULL,
    category TEXT NOT NULL DEFAULT 'General',
    status TEXT NOT NULL DEFAULT 'Unverified'
        CHECK(status IN ('Unverified','Verified','Disputed','Rejected')),
    confidence INTEGER NOT NULL DEFAULT 0 CHECK(confidence BETWEEN 0 AND 100),
    notes TEXT DEFAULT '',
    created_by INTEGER,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(created_by) REFERENCES users(user_id) ON DELETE SET NULL
);

-- 3. SOURCES: Primary evidence citations
CREATE TABLE sources (
    source_id INTEGER PRIMARY KEY AUTOINCREMENT,
    source_name TEXT NOT NULL,
    source_url TEXT NOT NULL,
    credibility INTEGER NOT NULL DEFAULT 3 CHECK(credibility BETWEEN 1 AND 5),
    evidence TEXT DEFAULT '',
    added_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 4. CLAIM_SOURCES: Many-to-Many junction table
CREATE TABLE claim_sources (
    claim_id INTEGER NOT NULL,
    source_id INTEGER NOT NULL,
    relation_note TEXT DEFAULT '',
    PRIMARY KEY(claim_id, source_id),
    FOREIGN KEY(claim_id) REFERENCES claims(claim_id) ON DELETE CASCADE,
    FOREIGN KEY(source_id) REFERENCES sources(source_id) ON DELETE CASCADE
);

-- 5. VERIFICATION_HISTORY: Audit trail ledger
CREATE TABLE verification_history (
    history_id INTEGER PRIMARY KEY AUTOINCREMENT,
    claim_id INTEGER NOT NULL,
    old_status TEXT,
    new_status TEXT NOT NULL,
    comment TEXT DEFAULT '',
    changed_by INTEGER,
    changed_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(claim_id) REFERENCES claims(claim_id) ON DELETE CASCADE,
    FOREIGN KEY(changed_by) REFERENCES users(user_id) ON DELETE SET NULL
);

-- 6. INDEXES for fast filtering
CREATE INDEX idx_claim_status ON claims(status);
CREATE INDEX idx_claim_category ON claims(category);

-- 7. SUMMARY VIEW: Left join aggregation
CREATE VIEW v_claim_summary AS
SELECT 
    c.claim_id,
    c.claim_text,
    c.category,
    c.status,
    c.confidence,
    c.notes,
    c.created_by,
    u.username AS author_name,
    c.created_at,
    c.updated_at,
    COUNT(cs.source_id) AS source_count,
    ROUND(AVG(s.credibility), 1) AS avg_source_credibility
FROM claims c
LEFT JOIN users u ON c.created_by = u.user_id
LEFT JOIN claim_sources cs ON c.claim_id = cs.claim_id
LEFT JOIN sources s ON cs.source_id = s.source_id
GROUP BY c.claim_id;

-- 8. AUDIT TRIGGER: Automatically logs status changes
CREATE TRIGGER trg_claim_update
AFTER UPDATE OF status ON claims
WHEN OLD.status <> NEW.status
BEGIN
    INSERT INTO verification_history(claim_id, old_status, new_status, comment)
    VALUES(NEW.claim_id, OLD.status, NEW.status, 'Status updated via automated trigger');
END;
```
